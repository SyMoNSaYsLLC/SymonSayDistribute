## One key, one file

The gateway accepts one static key, generated by the operator, stored in the file
`SYM_GW_KEY_FILE` names (default `~/.config/symoneural/gateway-9001.key`, mode 0600). Clients
send it as `x-api-key` or `Authorization: Bearer`.

- Compared in constant time (`hmac.compare_digest` in `gateway.py`).
- Re-read from the file on every request: rotation is "replace the file", no restart.
- Never logged, never echoed in an error, never in a response.
- Every document and script names *where* the key is and never *what* it is. Scripts read it
  with `$(cat "$SYM_GW_KEY_FILE")` inside the request and nowhere else.

## Loopback by design

All three units bind `127.0.0.1`. Public reach is the operator's edge proxy and tunnel, which
terminate TLS and forward to loopback; the units never bind an interface. The web interface
reaches the gateway through a same-origin rewrite (`/gw/*`), so the key never reaches a
browser.

## Fail closed

| Condition | Behaviour |
|---|---|
| key file missing or unreadable | every credentialled route answers `500` in the error envelope; `/health` still answers |
| wrong or missing key | `401 authentication_error` |
| unknown model id | `404 not_found_error` — including the upstream checkpoint's own name, which is never offered |
| engine unreachable | `503 api_error`; the gateway does not fall back to anything |

## What never enters a repository

Enforced by `.gitignore` patterns **and** by the gate below scanning every blob of history:

- credentials: `*.key`, `*.pem`, `*.env` (but `*.env.example`), `credentials*`, `secrets*`
- weights: `*.gguf`, `*.safetensors`, `*.onnx`, `*.pt`, `*.pth`, `*.bin`
- project-level agent configuration (`.claude/`)
- operator identifiers — account ids, personal e-mail addresses, home-directory paths — are
  listed for review by the gate; the product repository was scrubbed of them on 2026-09-18
  (they remain in earlier history; see the assessment in the estate's reports)

Two years after each release this repository becomes Apache-2.0. Write everything in it as if
it were public today.

## The ship gate

`tools/ship-gate.py` runs over the staged artifacts and the repository history before anything
is published (`tools/cut-release.sh` refuses otherwise). It re-derives every census itself:

- licence class of every component in every closure — strong, network, weak (file/library),
  use-restricted, proprietary third-party, unknown — from wheel metadata, package manifests,
  ELF `NEEDED` and crate closures;
- attribution present in `THIRD-PARTY-NOTICES` for every permissive component;
- secrets by content pattern and by file name, inside archives too;
- weights inside artifacts; third-party marks in artifact names;
- known vulnerabilities (HIGH/CRITICAL fail; an unavailable scanner is recorded, never a pass);
- August-2026 inputs.

Policy is data: `tools/ship-gate-policy.json`, with every recorded exception and who ruled it.

## Reporting a problem

Open an issue in the repository with the `x-request-id` of the affected request and the
gateway log line that carries it. Do not include the key, the key file, or a request body that
contains private data.
